# Canon divergences

`zenoh_dart` binds canon zenoh-c 1.8.0. This page lists the places where the package deliberately does not bind a canon symbol, or binds it differently, and why — every divergence decided and recorded so far. **It is not yet a complete census:** the check that everything else in canon is bound is part of the sign-off before 1.0.0, so a canon symbol you cannot find in the API or on this page is worth an issue.

"Unstable in canon" means zenoh-c declares the symbol only in a build with `Z_FEATURE_UNSTABLE_API`. This package's `unstable` variant, imported through `package:zenoh_dart/zenoh_unstable.dart`, binds part of that API; the rows below name the parts it does not.

| Canon symbols | What this package does | Why | Reason class | Revisit when | Recorded |
|---|---|---|---|---|---|
| `z_shm_data`, `z_shm_len` | Not bound, permanently. The content of a shared-memory payload is read through the ordinary bytes path (`ZBytes`), which is bound. | Handing out a raw pointer into shared memory is a hazard: a received payload's segment belongs to the sender's provider, so the pointer would reach memory this package does not own, with no lifetime guarantee beyond the callback. | equivalent by design | — (permanent) | 2026-09-02 |
| `z_shm_provider_available` | Not bound. | Measured to return a constant 0 at every point in a provider's life (new, after allocation, when exhausted, after garbage collection) on `z_shm_provider_default_new`, the only provider this package constructs. A value that can only ever be 0 would invite capacity logic built on a constant. | removed by decision | If a provider type that actually populates it is bound. | 2026-09-02 |
| `z_shm_provider_alloc_gc_defrag_async`; `z_posix_shm_provider_new`, `z_posix_shm_provider_with_layout_new`; `z_shm_provider_alloc_layout`, `z_precomputed_layout_*` | `z_shm_provider_alloc_gc_defrag_async` is bound, as `ShmProvider.allocGcDefragAsync` (in `zenoh_unstable.dart`). The provider constructors and the precomputed-layout API are not bound. | These are unstable in canon and are bound only when a concrete use needs them. Asynchronous allocation had one, because blocking allocation can wait indefinitely on a request the pool cannot satisfy; it works on the default provider, so none of the others is needed. | unstable in canon, not bound by decision | When a concrete use needs one of the unbound symbols. | 2026-09-02 |
| `z_shm_provider_new`, `z_shm_provider_threadsafe_new`, `zc_shm_provider_backend_callbacks_t`, `z_shm_provider_map` | Not bound: custom shared-memory backends are not supported. | Unstable in canon. | `z_alloc_layout_*` | Not bound. | Deprecated in canon, which points to `z_shm_provider_alloc_layout` instead (also not bound; see above). | deprecated in canon | — | 2026-07-14 |

| `publisher_options` (in `ze_advanced_publisher_options_t`), `subscriber_options` (in `ze_advanced_subscriber_options_t`), the cache reply `congestion_control`, `priority` and `is_express` (in `ze_advanced_publisher_cache_options_t`), the history `max_samples` and `max_age_ms` (in `ze_advanced_subscriber_history_options_t`), `query_timeout_ms` (in `ze_advanced_subscriber_options_t`) | Not bound: the advanced publisher and subscriber leave these at canon's defaults. | Unstable in canon, and no use has called for them. | `zc_cleanup_orphaned_shm_segments` | Not bound. | Unstable in canon. It is a host-wide utility that cleans up leftover shared-memory segments, and nothing in this package needs it. | unstable in canon, not bound by decision | — | 2026-08-19 |
| `z_shm_client_*`, `z_posix_shm_client_new`, `z_shm_client_storage_*`, `z_ref_shm_client_storage_global`, `zc_shm_client_list_*`, `z_open_with_custom_shm_clients` | Not bound. | `z_bytes_get_reader`, `z_bytes_reader_read` | Used inside the package, not exposed: the native layer reads a payload out through them, and Dart code receives the bytes whole through `ZBytes.toBytes()`, or slice by slice through `ZBytes.slices`.
